# CLAUDE.md — Market Square Frontend

Market Square: the social, discovery, streaming and ARK Store surface of the Ark/WorldStreet platform. Sibling app to `../wsws-frontend` — follow its conventions; do not import from it.

## Tech Stack
- Next.js (App Router) + React 19 + TypeScript, pnpm
- Tailwind CSS v4 — theme in `app/globals.css` via `@theme inline`; NO component library
- Auth: Privy (`@privy-io/react-auth` client, `@privy-io/node` server verification)
- Server state: TanStack Query v5. NO global state manager (no Redux/Zustand); React local state for UI
- Validation at boundaries: zod v4. Toasts: sonner. Animation: motion

## Architecture (layers, imports point downward only)
- `app/` — routes + BFF route handlers. Owns no business logic
- `features/` — vertical slices (`feed`, `streams`, `store`, `profile`); slices NEVER import each other; each exposes only its `index.ts` barrel
- `components/ui/`, `hooks/` — shared presentation/behaviour
- `lib/` — pure cross-cutting: api client, envelope, formatters, brand

## API rules
- Backend envelope: `{ success: true, data } | { success: false, error: { code, message, details? } }` — `unwrap<T>()` in `lib/api/envelope.ts` throws typed errors
- Data flow: component → hook (useQuery/useMutation) → feature api client → `app/api/market-square/[...path]` BFF proxy → `${WSAPI_BASE_URL}/v1/market-square/*`
- Components NEVER call fetch directly or hold base URLs. The BFF verifies the Privy session and forwards `Authorization`
- **Run `pnpm check:public-routes` whenever routes change.** It fetches the backend's `openapi.json` and diffs the public-GET set against `isPublicGet` in BOTH directions, exiting non-zero with a readable diff. `MS_API_BASE=… pnpm check:public-routes` (or `--base`) points it at another environment. It needs a live backend, so it is not in `pnpm test` — the hand-written table in `lib/api/public-routes.test.ts` covers the same ground offline. **Keep both.** Three public routes (`categories`, `search`, `topics`) reached production gated at 401 before this existed, each found only when somebody hit the 401 by hand
- Which GETs a signed-out visitor may read lives in `lib/api/public-routes.ts` (`isPublicGet`), and its **source of truth is the backend's `openapi.json`**: a GET is public exactly when its operation carries no `security` requirement. `lib/api/public-routes.test.ts` asserts that table in **both** directions — a route that silently becomes secured upstream fails as loudly as one that becomes public. Re-derive both from the spec (the `jq` one-liner is in the file header) whenever backend routes land; never patch the predicate one bug at a time
- A public GET skips our session check but still forwards the caller's token when present, so `likedByMe` / `bookmarkedByMe` keep resolving for signed-in readers
- Query keys are tuples: `["ms","feed",lane]`, `["ms","stream",id]`; mutations invalidate subtrees
- Monetary/KASH amounts are decimal strings end-to-end — never parseFloat for arithmetic, only for display formatting

## Design language (Ark)
- Pure black `#000` background, white text, silver accent `#d4d4d8`
- **The accent colour of the product is PURPLE, not gold.** The gold sweep repainted every amber surface across eight files. `--color-featured`, `--color-featured-deep`, `--color-featured-hi` and `--color-featured-chip` **no longer exist** — they were deleted rather than left dead, because a token named "featured" is exactly what invited gold to spread as decoration. `ws-featured` is now `ws-premium`, and `Pill`'s `featured` tone is now `premium`. If you find `text-featured` anywhere, it is stale
- **Purple is one shared ramp with two named stops. Keep the tokens separate; do not add a third purple.** The stops are genuinely related — `ws-btn-arena` runs a gradient straight from one into the other — so do not describe them as unrelated hues. What must not collapse is the *semantics*, not the palette
  - `--color-create` `#9f65fd` → `--color-create-deep` `#5b05e6`, utility `ws-btn-create`. Role: **the compose CTA**, and the ramp's **light stop**
  - `--color-spotlight` `#7e3beb`, `--color-spotlight-chip` `#6829ce`, `--color-spotlight-chip-ink` `#c27aff`, utility `ws-spotlight`. Role: **featured citizens**, and the ramp's **dark stop**
  - **The sidebar's active nav item renders its tint and border from `--color-create`, not the measured hex.** The design measures `#AD46FF` there — a third purple. At the alphas actually used (11% fill, 30% border on black) it composites to ΔE2000 **2.07** and **3.43** against `--color-create`, i.e. at or barely above the just-noticeable threshold, and only on a 1px line and a near-black wash. The design's own icon fill in that item is `#9F65FD` = `--color-create` exactly, so deriving the tint from the same token also makes the item internally consistent rather than pairing a glyph with a different purple behind it. Two stops stand; do not add `#AD46FF`
- **Both together** = the featured hero's **live-arena CTA**, `ws-btn-arena`: `linear-gradient(131.93deg, --color-spotlight -10.87%, --color-spotlight 43.15%, --color-create 109.17%)`. Reuse these two tokens for any new purple surface rather than defining another
- **Which stop to reach for is a contrast decision, not a taste one.** On black, `--color-create` is **5.77:1** and `--color-spotlight` only **3.71:1**; white on `--color-spotlight` is **5.66:1** but on `--color-create` only **3.64:1**. So: **purple ink on a dark ground → the light stop** (`text-create`: notification glyphs and unread dots, VIP tier labels, the chat podium rank, post-card active state, admin chips, `Pill tone="premium"`); **solid purple fill → the dark stop with white ink** (`bg-spotlight text-white`: every unread count badge, admin count pills and tabs, the rank-1 podium badge). Never `bg-create` behind small white text, and never `text-spotlight` as small text on black — both fail AA
- **`--color-coin` `#e8b74a` is the only gold left, and it means MONEY.** Just the `IconCoin` glyph beside a KASH amount in the gift tray and the gift button that spends coins, both in `stream-room.tsx`. Gold-for-currency is a real convention carrying real information, so it survived the sweep deliberately; the token is named for what it is so it cannot be reused as decoration. **If a surface is not currency, it does not get this token** — VIP tiers, "premium" and "top-ranked" are all purple now
- Greyscale ramp; panels `#0a0a0a`; semantic green `#7ce7b0` / red `#f6a5a5` for value deltas only
- Type: Geist (body, weight 500), bold display face with `-0.01em` tracking exposed as `ws-display`
- Surface utilities: `ws-card` (22px radius, 5% white fill, 12% white border, inset top highlight), `ws-inset` (16px radius, black/35 fill), `ws-glass` (6% white + backdrop blur), `tnum`
- Rounded/pill shapes, radial-gradient page washes, respect `prefers-reduced-motion`

## Home (Market Square design)
- Home is **card-based**, not divider-based: posts, streams and activities are `ws-post` slabs with gaps. `ws-row` stays for the other column surfaces — do not mix the two on one page
- `ws-post` is an **outline**, not a panel: transparent fill, one hairline at 10% white, 16.5px radius. Depth on home comes from the border, never a lighter fill
- Column order: breadcrumb (in `AppShell`, spanning column + rail) → section switcher + Schedule Stream/Create Post → stories strip → featured hero → lane tabs → card timeline. Home gets its own wider column (`md:max-w-[720px]`); everything else stays at 600px
- The section switcher and both creation actions live inside **one long outlined pill** (`ws-tabbar`): `Feeds · Discover · Messages · Notifications · Arkmarks`, then Schedule Stream and Create Post. Active Feeds is `ws-btn-silver`; Create Post is `ws-btn-create` (the violet ramp — see Design language)
- Lane tabs are `For You · Live Streaming · Reels · Following · Trending`. The rule is full-width at 8% white with a **white** active segment — not amber. Every one is a real backend lane (`reels` and `trending` included) — never filter a lane client-side
- Clips render through `InlineVideo`: muted autoplay once 60% is in view, pause + re-mute on exit, sound only on an explicit tap. Under `prefers-reduced-motion` it does not autoplay and keeps native controls. Detect video with `isVideoPost` (backend `mediaKind` first, URL sniffing as the fallback), never `isVideoUrl` alone
- A repost arrives as the **original post** with `repostedBy` on the FeedItem; the card keeps the original author and the attribution line names who passed it on
- Stories are **portrait cards** on desktop (100×96) and the **circular rail** on mobile (`StoriesRail`, 41px rings + names) — both share the grouping, seen/unseen semantics and the Instagram viewer
- Post actions: a tallies pill (comment / repost / like), the inline "Comment here…" pill, then share, **Arkmark** and a ringed 38px more-menu. `POST|DELETE /posts/:id/bookmark` and `GET /me/bookmarks` back the Arkmark; a 404 means "not deployed", so the control goes quiet (`useBookmarkPost().unavailable`) rather than faking a save
- A **liked heart is red** — `--color-like` `#e84a4a`, on every surface: the card tallies pill, the profile grid and the snap feed (burst included). It was amber until the 2026-08-25 design revision moved it off the accent; all four liked cards in the file changed together. It is its own token so it can never drift onto the purple ramp or back onto gold
- Everything that is not purple, red (`--color-like`), the live strip's `--color-live`, `--color-coin` or a value delta (`--color-up` / `--color-down`) stays on the **silver ramp**. Treat "it used to be amber" as no argument for making something amber — the sweep moved every one of those surfaces, and the tokens it used are gone
- Slices never import each other, so `components/layout/*-screen.tsx` composes across them: `home-screen` joins profile's `FollowPill` + streams' live count into the feed, `profile-screen` joins messages' `Message` button into the profile — the same route-slot pattern the stream room uses

## Identity chips
- Three independent signals sit on an author line and can co-exist: `VerifiedBadge` (verification), `RoleChip` (role), and `OrgBadgeChip` (the design's MARKET / ARK lockup)
- `orgBadge` is `'market' | 'ark' | null`, assigned **admin-only** and deliberately **not derived from role** — product decides who carries one. Never infer it from `role`, `verification` or anything else; when it is null, render nothing
- The lockups are brand artwork, so `components/ui/org-badge-glyphs.tsx` keeps their real fills rather than recolouring to `currentColor` (unlike `design-icons.tsx`). Chip geometry is the design's: 21px-radius capsule, 4% white fill, glyph 7px tall
- **The border is per-badge, not shared.** The 2026-08-25 revision gave the MARKET chip a solid `#008CFF` 1px ring; ARK was checked separately in the same file and kept the 19% white hairline. The fill is still 4% white on both — the blue is the ring, not a filled background. In the design the two lockups are also distinguishable by artwork: MARKET's flanking marks are solid white, ARK's are `#979797` at 18%
- The schema defaults to null and `catch`es unknown values, so a backend without the field — or with a future third badge — parses cleanly instead of blanking the surface. `lib/api/schemas.test.ts` pins that

## Counts, badges and unread
- **Never derive a badge from a loaded page.** `GET /me/unread` answers `{ messages, notifications }`, both global, in one call — `hooks/use-unread.ts` owns it and polls at **45s**. Anything that changes a count locally (send, mark-thread-read, mark-notifications-read) calls `useRefreshUnread()` so the badge moves immediately; the poll only catches other people's activity
- **`isFollowing` is optional, never defaulted.** `undefined` means "this payload does not carry the follow edge", which is not the same as "you do not follow them" — `GET /spotlight` omits it entirely today. Defaulting it to `false` made every spotlight refetch stamp "Follow" back over a follow the viewer had just made. Follow controls read `useIsFollowing` (`features/profile/lib/follow-state.ts`), which layers the session's own click intent under the server's answer: the server wins the moment it carries the field (so nothing changes when the backend ships it), the intent only fills the gap when it does not, and with neither the answer is `false` — a missing field can never render a fabricated "Following". The decision itself is pure and pinned in `lib/follow-resolve.test.ts`
- `GET /categories` counts are authoritative and `real-world-assets` / `prediction-markets` return `count: null` **by design** — other services own that data. Null renders as an em-dash, never `0`
- The category rail renders the API's own labels and order; `PRESENTATION` in the rail maps `key` → href + glyph only

## Messages (1:1 DMs)
- `POST /conversations { userId }` is idempotent from either side; `GET /me/conversations` (global `totalUnread`), `GET|POST /conversations/:id/messages`, `POST /conversations/:id/read`. Non-participants get FORBIDDEN on every conversation route even with a valid id
- Messages are ≤2000 chars (rate limited 30/min) — the composer stops at the same cap rather than letting the service reject it
- The thread returns **newest-first**; the view reverses it to read oldest-first
- Realtime publishes `market-square.message.sent` **without the body**, so it is a refetch signal, not a payload. Until ws-gateway carries it, an open thread polls at 5s (the live room's chat cadence). Do not build a websocket for this
- Opening a thread is the acknowledgement: mark-as-read fires once per thread, not on every poll tick

## Layout (three-column shell)
- `AppShell` centres a max-1280px frame: labelled sidebar (icon rail below `xl`), a 600px centre column, then `RightRail`. Routes in its `WIDE` list (store, operations, studio, schedule) drop the rail and spread; `/live/[id]` renders bare
- **Composing is global, and the shell owns it.** All three entry points — the sidebar `Post` button, the desktop floating `+` (the design's 53×53 silver circle at the column's outer edge) and the mobile `+` — open one `ComposeSheet` **in place**. They used to be `<Link href="/?compose=1">`, so posting from `/store` threw you home and lost the page. Which surfaces carry it is `lib/compose-surfaces.ts` (`allowsCompose`), pinned by tests: everything except `/live/:id`, `/studio/:id`, `/admin/**`, `/operations/**` and `/auth` — note the index routes `/studio` and `/live` keep it, which is why those rules carry a trailing slash. The composer lives in the feed slice, so `components/layout/compose-sheet.tsx` joins it through the feed barrel — the same route-slot pattern as `home-screen`/`profile-screen`; never deep-import it. Publishing from a non-feed surface shows nothing new on screen, so the sheet toasts with a **View post** action into `/p/:id`
- Home keeps its own **in-timeline** composer for the in-page entry points (`?compose=1`, `?compose=story` from the stories rail and the empty states). The rule: shell chrome opens the sheet, in-page affordances open the inline composer
- Body copy in the column is **15px**; the column is a continuous timeline, not stacked cards — rows use `ws-row` (hairline divider + hover tint), never `ws-card`. `ws-card` is now only for detached objects: sheets, tiles, dashboard panels
- Column utilities in globals.css: `ws-row`, `ws-head` (sticky blurred header), `ws-rail` / `ws-rail-row` (rail modules), `ws-field` (pill input), `ws-nav` (sidebar item), `ws-action` (timeline action with a growing halo), `ws-hair` (the shared hairline border colour)
- Every non-timeline column surface opens with `ColumnHeader` (+ `ColumnTabs`) from `components/layout/`; loading uses `RowSkeleton`, not `CardSkeleton`
- The rail leads with what a plain timeline lacks: `LiveNowRail` then `TicketsRail` (both from the streams slice), then `WhoToFollowRail`. Rail modules live in their own feature slice and are exported from its barrel — `components/layout/` composes them
- Nav icons take a `filled` prop for their active state; read URL params with `useQueryParam`, never `useSearchParams` (its Suspense boundary delays hydration and desyncs user-dependent renders)
- `Sheet` carries the X dialog chrome: dismiss control, title, one pinned right-hand action (`action`), optional `tabs` strip, `back` for a step inside a flow

## Stories (Instagram pattern)
- The rail groups posts **by author** — one tile per person, a tap plays that author's set oldest-first, then rolls into the next author. `Your story` always leads with a `+` badge and points at `/?compose=story`
- **The strip carries live broadcasts as well as stories, and they are different objects.** Order is `Your story` → **live** → **the server's story order, unchanged**: live is the highest-urgency thing on the square and the only entry that expires while you look at it.
- **`GET /stories?scope=all`, never `scope=following`.** `following` returns only your own stories on an account that follows nobody, which made the rail look broken to every new user. `all` is server-ranked — own, then followed, then everyone, each band newest-first — and **that order is authoritative: the rail must not re-sort it**. An earlier client-side unseen-first sort flattened the bands, floating a stranger's unseen story above a friend's. Sorting unseen-first *within* a band is not possible either, since the payload carries no band marker. Seen state drives the **ring** only (silver vs drained), never tile position — which also stops the rail reshuffling under the viewer as they watch A live tile links into `/live/:id` (or `/studio/:id` when the viewer is the host) and **never** opens the 5-second story viewer; seen/unseen `localStorage` semantics are stories-only, since a stream is live or it is not in the strip at all. Live entries come from the **`live` feed lane** (`useFeed("live")`), which Home already fetches for the featured hero — so the strip costs no extra request and the rail stays inside the feed slice. That lane also carries scheduled activities and not-yet-started streams, so `status === "live"` is a load-bearing filter: **scheduled is not live**, and no viewer count is rendered because the list payload carries only `peakViewers`, never a current one
- The strip's live marker is `--color-live` `#ff0b0b` — the design's solid pill on the tile's bottom edge plus the same red at 40% as the tile ring (`ws-story-live`). This is the **strip only**; the live identity everywhere else is still `LiveBadge`, the black pill with a pulsing silver dot. It is deliberately not `--color-like`: a liked heart is not a broadcast
- Unseen carries the `ws-story-ring` gradient (silver, not Instagram's pink/orange); seen drains to `ws-story-seen`. `ws-story-gap` is the black ring/avatar gap that makes it read as a ring
- Seen state has no backend field: it lives in `localStorage` behind a `useSyncExternalStore` with an empty server snapshot. Every storage access is try/caught
- The viewer is a 9:16 card — per-story progress segments, hold-to-pause, left-third/right-two-thirds tap zones, arrow keys, desktop arrows outside the frame. Artwork-less stories get the seeded `GradientThumb` plus a lift and top/bottom scrims
- **Story media is contained, never cropped.** The frame is 9:16 but a story can be any ratio, so `object-cover` sliced the ends off every landscape photo. Media renders `object-contain` over a blurred, over-scaled (`scale-125 blur-2xl`) copy of itself — the Instagram/WhatsApp letterbox fill — so the card stays full-bleed without losing content. The blurred copy is `aria-hidden`; both layers sit under the tap zones (z-10) and the progress/header chrome (z-20). This is the **viewer** only: the timeline's `post-card` still crops to a ratio deliberately

## Explore
- The topic picker renders from `GET /topics` and **never** from an array in the component, so a new topic ships from the backend alone. Only the per-key glyph is a local decision, with a neutral fallback for a key the client has not seen
- Interests persist via `PUT /me/interests` and invalidate the feed and Explore, because a saved interest that does not change what you see reads as a no-op. Signed-out readers can choose; the sign-in prompt appears at save, which is the point it is actually required
- **Live counts are `viewerCount` ONLY, never `peakViewers`.** `viewerCount` is absent on list rows and therefore NULLABLE, not `0` — "no live count available" and "nobody is watching" are different claims. `peakViewers` is a historical high-water mark and may only be rendered under an explicit "peak" label (the post-live stats panel and the feed's stream cards do this correctly). Presenting a peak as a live audience is the kind of small dishonesty that makes every other number in the product suspect
- **OPEN QUESTION — the Explore card's viewer glyph.** The design draws it `#979797` on most cards and `#E84A4A` on some, and the meaning of that difference is *unconfirmed*: Figma returned 429 on every attempt across a whole session, so the node was never fetched. The current implementation guesses **red = the stream is live** (the only distinction the data supports) and greys everything else. **This is a guess, not a spec.** Confirm against the design before treating it as settled, and do not build further meaning on top of it

## Ark-originated streams are WATCH-ONLY here
- Ark broadcasts its own surfaces (casino games today) into Market Square as live streams. **Ark is where people participate; Market Square is where people watch.** A stream carrying an Ark product deep link is therefore a viewing surface, and the onward action is to go and join it in the app that owns it
- `isArkOriginated(deepLink)` in `lib/deeplink.ts` is the test, keyed on `deepLink.kind` against `ARK_PRODUCT_KINDS` — **never on a list of games**. A future Ark surface gets the right behaviour by adding its kind there, with no change to the stream room
- On such a stream the room **hides** the speaker-request control (both the desktop header and the mobile rail) and shows "Join the match in Ark" instead. Hidden, not disabled: the host is mid-match and will never approve a request, so a greyed-out button only invites "why is this off?"
- **Do not re-add the speaker control for consistency with native streams.** It is a dead end there, and `lib/stage.test.ts` fails if either entry point loses its guard
- Everything else about watching is unchanged and first-class: chat, reactions, hearts, viewer count, tickets, gifts. Native Market Square streams (no Ark deep link) keep the speaker-request flow exactly as it is

## Live room (TikTok pattern)
- Three panes: the nav rail, the centre column, and a collapsible LIVE chat column. The stage owns the whole viewport — `AppShell` renders `/live/[id]` bare
- **The rail is the way out of the room, so it can never be absent while the room is in its desktop form.** It runs from `lg` — icon-only at 72px, labelled at `xl` (250px) and `2xl` (304px) — the same collapse `AppShell`'s sidebar uses, and the width band every watch page lands in (YouTube's mini-guide is 72px, Twitch's collapsed rail 50px, expanded rails cluster at 240–256px). It was `xl:flex`, which left 1024–1279px with no rail, no back control and no wordmark. Below `lg` the full-bleed stage carries its own overlaid back chevron instead
- `STREAM_NAV` is **one entry per destination**. It used to carry four labels over two hrefs (Back + Discover LIVE → `/live`, Go LIVE + Creator tools → `/studio`), and marked `/live` `aria-current="page"` on a page that is `/live/:id`. Nothing in the rail is current — the rail only leaves. The footer's Company / Program / Terms & Policies were bare `<p>`s with no routes behind them; only the copyright line is real
- **Theater mode hides chrome; fullscreen fills the screen.** They were the same handler, so the control bar shipped two differently labelled buttons doing one thing. Theater now drops the rail and the chat column, is `aria-pressed`, exits on Escape or the same button, and brings the back chevron onto desktop so the exit survives. Chat's collapse control lives in the **header**, not inside the panel it hides — the in-panel-only version was a one-way door on desktop
- The centre column is a **vertical stack from `lg`**: header → 9:16 player → host handle → gift panel. Below `lg` it collapses to one full-bleed stage with everything absolutely overlaid. Never re-attach the player controls to a dock strip: they overlay the frame's bottom edge, and the `LIVE creator` badge, elapsed time and LIVE pill sit **inside** the frame, not in the header
- The vertical action rail (heart, gift, pulse, chat, share) is the **phone** pattern only. On desktop those actions live in the header (share, more, Subscribe, Follow, ticket), the frame's control cluster (pulse, request-to-speak) and the chat column (floating heart, anchored clear of the composer)
- Chat is **monochrome**: flat rows (avatar, grey name, white message), Host/role chips, no per-author colours or tinted bubbles. Top viewers is a podium — rank 1 large, 2 and 3 stacked beside it
- Player chrome uses real icons (`IconPause`/`IconRefresh`/`IconPip`/`IconFullscreen`/`IconVolume`/`IconChevronDown`), never glyph characters — they align to the same 20px grid as the rest of the UI
- Gifting is governance-gated by `MARKET_FLAGS.liveGifts`. With it off there is no tray, so the dock collapses to the 48px control bar and **all** coin chrome disappears (sidebar `Get Coins`, the balance bar, the tray toggle). Gate on `dockExpanded`, never the raw `giftTrayOpen`
- **A capture failure is never just "denied".** `usePublisher` classifies `err.name` through `classifyCaptureError` (`lib/media-errors.ts`, pinned by `lib/media-errors.test.ts`) into four states with four different remedies: `denied` (NotAllowedError/SecurityError — a permission the user must change), `device-busy` (NotReadableError/**TrackStartError** — another app or browser tab holds the device), `device-missing` (NotFoundError/OverconstrainedError) and `failed` (unknown — show the real message, never a permission prompt). Collapsing these told a guest whose camera was held by a second browser profile to "allow camera access", pointing at a prompt that will never appear. The helper also unwraps `cause`, because LiveKit re-throws over the original DOMException
- **The publisher can never spin forever.** A connect that has not settled in `CONNECT_TIMEOUT_MS` (15s) becomes `timeout`, and every terminal state (`PUBLISHER_FAILURES`) renders a message plus a **Retry** that tears down and re-runs the connect. LiveKit `ConnectionError` and a failed `room.connect` surface their message rather than being swallowed. `RoomEvent.Disconnected` only means `failed` *after* the attempt settled — during connect it is the timeout's job
- **Camera failure falls back to audio-only rather than failing the join.** If video cannot be acquired but the mic can, the guest joins with audio, `audioOnly` is true and the panel says "Joined with microphone only — camera unavailable". `toggleCam` is the recovery path: `setCameraEnabled(true)` re-acquires on demand, so video comes up once the device frees, and its own throw is classified too instead of rejecting unhandled. Only when *both* fail is the join refused
- **The host's queue shows `approved`, not "on stage".** Approval is a decision the host made; whether the guest's browser actually acquired a device and connected is not in the speaker-request payload, so a confident green "is on stage" was asserting something unobservable while the guest sat stuck. Real presence needs the room's remote participants threaded from the publisher into `SpeakerRequestQueue` — not wired yet
- `Suggested LIVE creators` reads the live stream list minus the current room; the header identity falls back to the stream title when `owner` is not hydrated (list and detail payloads do not always carry the profile). In the collapsed rail it degrades to avatars alone, so each row carries its own `aria-label` — the name text is `display:none` there and cannot supply the accessible name

## Conventions
- Named exports only (no default exports except Next.js route files)
- `clsx` + `tailwind-merge` via a `cn()` helper
- Loading skeletons + inline error states for every query; empty states designed, not blank
- `.env`: `WSAPI_BASE_URL`, `NEXT_PUBLIC_PRIVY_APP_ID`, `PRIVY_APP_SECRET`
- Gates: `pnpm lint && pnpm typecheck && pnpm test && pnpm build` must pass
- Tests run on Node's built-in runner (`node --test`, zero dependencies) over `lib/**/*.test.ts`, using Node 24 native type stripping — hence `allowImportingTsExtensions` and the real `.ts` import specifier in test files

## Do NOT
- Import from wsws-frontend; use any component library; use Redux/Zustand/Context-as-store; put logic in route files; use floats for money; use `any`
